# Plan: review-916-917

## What Sean asked for
Act on the maintainer's review of #917 and their comment on #916.

## What we found
- **#917 (generator expressions)** is approved. The maintainer asked for two small things:
  1. **A rebase.** Only `tests/test_unit_eval.py` conflicts with upstream master, because both sides added tests at the end of the file. We checked this: `eval.py` and `docs/reference.rst` merge cleanly.
  2. **One docs sentence.** The docs say an element can't call "a service with `blocking=True` whose handler has to wait". The maintainer says that undersells it: any `blocking=True` call to a pyscript service fails, even when its handler doesn't wait, because pyscript runs the handler in its own task (and most Home Assistant services do I/O too). They suggest just saying that an element can't make a service call with `blocking=True`.
- **#916 (classes, `super()`, inherited `__init__`)** "needs updating after #915 was merged". #915, from another contributor, changed how pyscript stores classes. Before, a module-level class was kept in a placeholder box that had to be unpacked in many places. Now the class itself is stored, and annotations that name the class being defined are filled in after the class exists. Two places in `eval.py` conflict:
  - in `ast_classdef`, where #915 added the "fill in pending annotations" step at the same spot where #916 records the class for `super()`;
  - in `ast_attribute`, where #915 removed the module unpacking that #916's diff still carries from the old code.
  `tests/test_unit_eval.py` also conflicts (both added tests at the end). Beyond the conflicts, other parts of #916 may still unpack those placeholder boxes, which is no longer needed.
- Upstream master is now `e1ff103` (after #915, #913 and #914). #918 (property/classmethod) also conflicts now. Our plan in batch 3 was to rebase it after #916 merges, so it isn't part of this job.
