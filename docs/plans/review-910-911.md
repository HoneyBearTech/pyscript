# Plan: review-910-911

## What Sean asked for

## What we found
- **#910 (`functools.wraps` decorators, #808)** is approved, with one fix. Methods on a class instance return the wrong doc string. `obj.method.__doc__` gives `"Class for a callable pyscript class instance function."`, which is the doc string of pyscript's own helper class, instead of the method's doc string. That happens with or without `wraps`. The cause: in `eval.py`, `EvalFuncVarClassInst` has its own class doc string, and that hides the `__doc__` property it inherits from `EvalFuncVar`. The maintainer's fix is to add `__doc__ = EvalFuncVar.__doc__` after its `__slots__`.
  - They also made a note that needs no change: a decorator that returns a different, existing function (`def deco(fn): return other`) renames `other` too. We'll just acknowledge it in the reply.
- **#911 (relative imports in an app's subfolders, #726)** got a "this is the right fix" comment, but not an approval yet. The maintainer wants scripts that use the old workaround (`from .subfolder.a import foo` inside `subfolder/b.py`) to keep working for now:
  - resolve the import with the new rules first;
  - only if no file is found, try again with the old rules, which used the importing package's folder as the base (so each context has to remember that base);
  - when the old rules are used, log a warning that this form is deprecated and will be removed in a future release, and say how to write the import instead;
  - name each module's context after the file's location (`apps/myapp/subfolder/a.py` gives `apps.myapp.subfolder.a`), not after the importer's name. Then both routes load the same context, and the duplicate "phantom" contexts can't come back;
  - add a copy of our test that uses the old import in `subfolder/b.py`, and check the warning.
  They tried about 40 lines in `module_import` (`global_ctx.py`) on top of our branch, the full test suite passed, and they shared it for us to use or adapt.
- Both PRs still merge cleanly with upstream master. The maintainer didn't ask for a rebase, so each fix goes on as a new commit, with no force push.
